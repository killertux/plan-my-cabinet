Plan My Cabinet designs furniture made from sheet goods (MDF, plywood): boards in 3D, the stock sheets they are cut from, a guillotine cut plan, hinges and doors. This server edits ONE project in memory; nothing reaches disk until save_project (absolute .pmcab path). The user can then open the file in the Plan My Cabinet app.

Geometry. A board is a rectangular blank: local X = length, Y = width, Z = thickness (the thickness comes from its material). Positions are millimetres, rotations degrees (intrinsic X, then Y, then Z), relative to the parent assembly unless frame is "world". World axes: X to the right, Y toward the back (the cabinet front faces -Y), Z up. Presets: stand_up = side panel (length up, thickness toward -X); lay_flat = bottom/top/shelf; rx 90 = front or back panel (width up, thickness toward -Y). Templates put the carcass front at Y = 0 and the left side's outer face at X = 0; overlay doors sit at y = 0 with rx 90. Faces are named -x/+x (length ends), -y/+y (width edges), -z/+z (broad faces); place_board_on_face puts one board's face against another's and is the easiest way to assemble without arithmetic.

Units and references. Numbers are millimetres. Strings may carry units ("60 cm", "23 5/8 in", "2'"); values that are not whole micrometres are refused unless allow_rounding is true. Money is "12.34" in the project currency; null = unknown. Any object can be named by id, a unique name, a unique id prefix (8+ hex), or for stock an alias like S1; materials also by name + thickness ("White MDF 18"). Ambiguous names return candidates — then use ids.

Seeing. You cannot see the app, so check your work: describe_scene lists every board's position, which boards touch and which INTERSECT (an overlap is a design error — fix it before continuing). render_view / render_views return pictures (numbers match the legend; hide the doors or carcass to look inside, `only` isolates parts). render_sheets draws the cut plan; render_door_opening swings a door.

Workflow. generate_template (base, wall, drawers) or new_project + create_material + create_boards → adjust (resize_board, set_board_pose, place_board_on_face, group_objects) → describe_scene + render_views → add_needed_sheets (standard materials) or create_stock + auto_place → get_diagnostics until boards_with_problems is empty → prices, cut fee, confirm kerf (set_stock_prices, set_project_settings) → optimize_cut_plan then apply_optimization → render_sheets → add_hinges per door (mount, count, positions and K/R are chosen for you) → create_door → render_door_opening → get_diagnostics → save_project.

State. Every change returns the new revision, undo_steps and warnings; undo reverts. Pass expected_revision to guard against surprises. Optimizer results go stale on any change: apply right after searching. delete_object cascades (use dry_run first). Ask the user before overwriting files, discarding unsaved work, or choosing prices. Hinge data is reference information, not drilling certification. Call get_guide for details and examples.
