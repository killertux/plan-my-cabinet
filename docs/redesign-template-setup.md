# Welcome template setup: domain integration

`src/template_setup.rs` owns a draft independent of the active document. Create `TemplateSetup::new(kind, project_name, currency, input_unit)` when a template tile opens. Set `dimensions` with `ProposedLength::new(Conversion)` from the existing input parser, set `drawer_count`, add draft materials (name, thickness proposal, grain, optional sRGB color), then explicitly map every `kind.roles()` entry to a draft material ID. Roles may share an ID. Do not copy an open project's material IDs, stock, allocations, or editor into this setup. A nested New material modal should edit a *separate* draft and call `add_material` only when it is accepted; cancelling that modal leaves the parent setup and its focus intact.

Call `review()` after edits. Errors identify project/material names, missing fields/roles, unconfirmed rounding, or the recipe's affected geometry field. A `NeedsConfirmation` proposal supplies the suggested micrometre value but is blocked until `confirm_rounding`; replacing the proposal clears consent. The returned candidate provides ordered individual boards (the BOM), parent assemblies, thicknesses, dimensions, poses, and a `TemplateDatums` Y-axis front/carcass/rear/back diagram model. Render the actual recipe assumptions and clearances beside that data; these boards are ordinary starting geometry, not certified slide fit or machining. `fits` follows candidate order with actual first-fit outcomes on the disposable fresh project. Welcome's fresh project has no stock, so all parts correctly preview as `NoFit`/unallocated; link to Stock after creation. The preview is disposable: UUIDs in it must not be retained as selection/commit IDs. Repeated review, edits, and cancellation leave the existing document and history untouched.

When Generate is requested, keep the setup alive while the host resolves the current edit/repair/pose navigation decision and unsaved-document replacement flow (including Save picker, save failure, Stay/Cancel). Only after every guard succeeds call `setup.generate()`. It validates again, builds an offscreen fresh editor, maps draft materials to fresh IDs, inserts materials, colors, assemblies, and recipe-ordered boards in **one** `ProjectEditor::transact`, and attempts real first-fit independently for each board. On error, retain the old editor and setup. On success, swap the returned `GeneratedTemplate.editor` into the host, clear its file path, open Design, select `assembly_id`, expose `fits`/unallocated diagnostics, and discard the setup. The editor is dirty/unsaved; one undo removes both generation and staged materials, one redo restores the same IDs. Never register it in recents until an explicit successful save. Later board edits are independent ordinary transactions. Undo of the generation leaves the new empty project and does not restore the previous document.

The native Welcome tiles now open the staged Base, Wall or Drawers modal. Its project, materials, dimensions and review steps include a datum drawing, generated-dimension table, first-fit outlook and a no-slides/no-machining/no-certified-fit disclosure. The host keeps the modal draft through unsaved-project and pending-edit guards, including failed or cancelled saves. A successful generation selects the new assembly in Design and offers a Stock route when its parts remain unallocated. A project is added to recents only after a later explicit save. Headless tests cover the draft, guards and first-run Drawers path; native reference capture and compact bilingual interaction acceptance remain separate work.
