# Design viewport boundaries (task 6.1)

`src/viewport.rs` retains the presentation-only `Camera`, projection/ray/drag mathematics, picking and snap geometry, and the public `show_move` entry point. Its parameters and `DragAction` return contract remain unchanged, including the existing inverse-scroll-zoom argument. `show_move` orchestrates four private boundaries in order:

1. `viewport/controls.rs` draws the current camera/tool controls and applies camera commands. It consumes the project only to frame real visible bounds; it does not edit the project.
2. `viewport/canvas.rs` allocates the clipped canvas rectangle, updates camera aspect/height, and routes egui pointer and keyboard responses to selection, navigation and tentative Move actions. Picking and drag calculations use this allocated rectangle and the shared camera. A modal cancels an active drag; an active pose preview permits navigation without canvas selection/Move.
3. `viewport/scene_render.rs` generates mesh geometry, creates the camera uniform, and queues the WGPU callback. `install` still places persistent resources in egui-wgpu's renderer callback registry; the callback owns per-frame mesh/uniform data and resizes renderer-owned color/depth targets during `prepare`, then composites them in `paint`. Do not make GPU views local to `show_move` or release them before the paint pass.
4. `viewport/annotations.rs` projects transient Move snap markers and labels using the same camera and canvas rectangle, clipping the projected grid marker to the canvas.

The parent module is the only public integration surface (`install`, `show_move`, `Camera`, `Selection`, `MoveTool`, `DragAction`, `Projection`). No project pose or undo operation is performed by camera controls or scene painting; the caller continues to apply or cancel returned drag actions. Future overlays should use the returned canvas geometry internally and an egui foreground interactive layer so their pointer widgets win hit testing before the canvas. Modal isolation remains the caller's responsibility via `modal`.

`src/viewport/boundary_tests.rs` is a viewport unit-test module because the viewport belongs to the binary and the seams are private. It moves and resizes an egui canvas, checks projected board picks and Move previews against the shared camera calculations, and confirms a foreground overlay captures clicks over a selected board without changing selection or beginning a drag. The existing viewport picking, snapping, keyboard, preview, geometry, and WGPU target-size tests remain alongside it in `src/viewport.rs` and `scene_render.rs`.

This extraction introduces no new tool mode, scene style, dimension or hardware annotation, snap configuration, inspector, or native visual acceptance result. Those behaviors are specified in tasks 6.2–6.8.

## Task 6.2: camera and tool commands

`ViewNavigate`, `ViewMove`, `ViewFrame`, `ViewPreset` and `ViewProjection` are typed entries in `src/actions.rs`. The viewport controls and focused-canvas `F` shortcut use the same availability guard; modal input, active placement preview and active Move drag prevent incompatible tool switches. Camera choices modify only session camera state. A selected object's visible, transformed board/placeholder bounds drive Frame; with no selection it frames the visible scene, and a completely empty scene resets the camera. Hidden selected geometry cannot silently frame another object. Perspective framing includes near-corner depth, whereas orthographic framing uses constant view scale. Both modes share the CPU projection/ray basis and the WGPU uniform. Top looks exactly down world Z with X to the right and Y upward.

The toolbar shows Navigate/Move and the selected camera view/projection at normal widths; orbiting changes the view indicator to Free view rather than claiming a preset remains active. Below 640 logical points, Frame, presets and projection move into **View options**; below 290 points, tools join that overflow. The contextual hint describes drag/arrows to orbit, Shift-drag/Shift+arrows to pan, scroll/pinch/+/- to zoom and `F` to frame, without relying on a three-button mouse. Right-drag pan remains available. The former Orbit/Pan/Zoom button row is removed. Measure, styling, dimension guides and snap configuration belong to subsequent tasks.

The binary viewport tests compare GPU-uniform vertex projection, CPU projection and ray picking for both projection modes and all four presets; test framing at narrow/wide aspect ratios, and assert project pose/revision/undo isolation. Native visual comparison remains pending against the handoff capture.

## Task 6.3: scene presentation and review

`show_move` receives app-local `material_tint` and passes it only into mesh generation. Each visible board gets its material's optional saved sRGB channels or `NEUTRAL_MATERIAL_COLOR`; turning tint off selects the same neutral shading for every board without editing the project. The renderer shades faces independently of selection. Active amber and secondary cyan outlines, subdued unselected outlines, and transient face-source cyan/target magenta guides are distinct. During a live drag a grid/free candidate clears any old placement face guide; a face candidate takes visual precedence. Hidden board/assembly descendants contribute neither triangles, outlines nor floor-shadow bounds. The grid LOD still derives from project spacing and camera distance, while colored axes remain in world coordinates. A soft-edged, display-only ground patch at Z=-2 beneath visible XY bounds is rendered by the existing WGPU pass; it is not a pickable surface, exact cast-shadow calculation or manufacturing evidence.

## Task 6.6: independent snap assistance

`MoveTool` owns session-only face/grid flags, both initially enabled. The snap chip reports the active combination and the project's actual XY spacing, including a shortened label when the toolbar is narrow. Its popover exposes independent toggles and the spacing edit action, which opens the existing project-identity/revision-checked grid dialog with parsed units, bounds validation, rounding consent, and undoable commit. The controls are disabled during a modal, active pose preview, or drag; camera, selection and modal input boundaries are unchanged. Neither flags nor an Alt hold enter `.pmcab`, project revision, or undo history.

The Move drag evaluates eligible visible face candidates first, then an eligible XY grid candidate at the **project** spacing; Alt skips both and release reevaluates the current flags. Preview/source/target face guides appear only for an actual face candidate; the projected crosshair identifies a grid candidate even if grid lines have been decimated at that zoom. Grid rendering computes its integer-multiple display interval from the same camera and project spacing, and the popover labels that interval separately when it is coarser. Changing flags or spacing does not reposition committed boards; only accepting a dragged pose can do so.
